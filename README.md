# SANAD-Gabès

**Sensor-Assured Network for Autonomous Decisions** — *Before the grid acts, SANAD verifies.*
TSYP14 EnergyMind Tunisia challenge (IEEE PES / IES), Phase 1.

> Fictional process plant in the Gabès industrial zone. All parameters are simulation assumptions.
> No measurement originates from a real company.

SANAD is an explainable AI **trust layer** for a fictional 400 V industrial line (1 MVA incomer BUS1, seawater pump
PUMP1, process compressor COMP1, auxiliaries AUX1). For every anomaly it answers one question:
**is the plant misbehaving, or is the measurement lying?** It returns a verdict, a calibrated confidence (or
**UNCERTAIN**), a plain-English explanation, a governed action, and a hash-chained audit entry. It also emits a
**trusted data stream** labelled VERIFIED / ESTIMATED / SUSPECT / QUARANTINED. SANAD is advisory: it never actuates.

## Quickstart

```bash
pip install -r requirements.txt && pip install -e .     # Python >= 3.11 (tested on 3.13)

python -m sanad.cli generate     # synthetic 8-week dataset  -> data/generated/main/      (~15 s)
python -m sanad.cli run          # detect/diagnose/govern    -> data/processed/main/      (~25 s)
python -m sanad.cli evaluate     # metrics                   -> reports/metrics.{json,md}
python -m sanad.cli demo         # scripted demo scenario    -> data/processed/demo_scenario/
streamlit run app/Home.py        # dashboard
pytest                           # tests
```

The dashboard works **right after cloning**: a 2-week demo run (`configs/demo.yaml`, gzipped) and the scripted scenario
are committed under `data/generated/demo/`, `data/processed/demo/` and `data/processed/demo_scenario/`. After
`generate` + `run`, the full 8-week run `main` appears in the dashboard's *Run* selector. Use `--config configs/demo.yaml`
with any command to work on the small run.

Results: see **[reports/metrics.md](reports/metrics.md)** (generated by `cli evaluate`; every number there is computed by
the code on the held-out test block).

## How it works

| Goal | Modules |
|---|---|
| 1. Detect, and distinguish genuine events from data-quality problems | `sim/`, `inject/` (data) · `physics/` (relations R1-R10) · `detect/` (validity, EWMA/CUSUM, Isolation Forest) · `diagnose/` (signature matrix, 2-of-3 voting) |
| 2. Confidence, explanation, audit | `confidence/` (calibration, abstention) · `explain/` (templates, no LLM) · `audit/` (SHA-256 chain, `verify_chain`) |
| 3. Human-AI governance | `governance/` (policy, router, trust controls) · dashboard pages 2 and 5 |
| 4. Multi-node sharing | `noosphere/` (Pattern Card schema; protocol in docs) |

The **Trust Fingerprint** is the relation set R1-R10:

| ID | Relation | Independent paths? |
|---|---|---|
| R1 / R2 | S² = P² + Q², P = √3·V·I·PF inside a meter | no |
| R3 | meter CT current vs motor-relay CT current | yes |
| R4 / R5B | bus power / energy vs sum of feeders | yes |
| R5 | kWh register vs ∫P of the same meter | partly |
| R6 | winding temperature vs thermal model driven by the relay CT | yes |
| R7 | speed vs 120·f·(1 − s(L))/p | yes |
| R8 / R9 | voltage / frequency agreement across meters | yes |
| R10 | DE vs NDE vibration and load envelope | yes |

A **genuine event** keeps physics consistent while independent sensors move together. A **sensor fault** shows one path
disagreeing with the others: the 2-of-3 vote (meter CT vs relay CT vs bus-implied current) names the odd one out.
**Falsification** breaks the energy relations while sensor-health cues look fine. SANAD only accuses with an operator
in the loop.

## Dashboard (`streamlit run app/Home.py`)

1. **Live Plant**: single-line diagram with every sensor coloured by trust state, plus trends.
2. **Alert Queue & Case Card**: verdict, confidence gauge, runner-up, top factors, rules fired, explanation and actions; Approve / Override / Defer / Annotate.
3. **Trust Fingerprint**: R1-R10 residual heatmap.
4. **Audit Log**: search, *Verify chain*, and a tamper demo.
5. **Governance**: tiers, override rate, track record and adaptive autonomy.
6. **Noosphere**: Pattern Card schema and the shared/local table.
7. **Simulator Control**: the scripted 5-step demo, including a naive vs SANAD-protected load-limit controller.

The dashboard reads only precomputed outputs of `cli run` / `cli demo`; it never recomputes the pipeline.

## Scope and honesty notes

* Phase 1 runs on **synthetic data only**. The real-data adapters (UCI Steel, PVGIS Gabès, Paderborn) are interfaces
  with TODO stubs.
* Everything runs at 1-min resolution. GRID_SAG is therefore a sustained under-voltage (≥ 1 min), and inrush appears as a
  1-min average.
* Bearing degradation is time-compressed to a few days. CT drift and falsification durations are also compressed to fit
  8 weeks; see `docs/data_card.md`.
* The detector was developed on the same simulator family it is evaluated on. Treat the metrics as an upper bound for
  real data.
* Out of scope for Phase 1: autoencoder, SHAP, One-Class SVM baseline, PV, multi-node simulation, Docker, auth.
